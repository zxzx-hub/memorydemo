# 提示词 0：生成项目总约束 AGENTS.md

你是一名高级 Python 后端架构师和 Agent Memory 系统工程师。

请首先完整阅读：

```text
backend/docs/agent-memory-design.html
```

该文件是本项目的领域架构事实来源。请在仓库根目录创建或更新 `AGENTS.md`，把下面的工程规则写入其中，并在后续所有开发任务中严格遵守。

## 一、项目目标

实现一个可以本地运行和测试的多租户 Agent Memory Service MVP。

MVP 必须完成以下闭环：

```text
原始事件写入
→ 工作记忆更新
→ Consolidate Once
→ 并行形成证据、短期任务检查点、长期候选
→ 长期候选治理
→ 长期主记录
→ 精确检索、语义检索和关系检索
→ Context Package
→ 生命周期治理和删除
```

核心 MVP 先完成后端服务、数据库、测试和演示脚本。仓库可以包含独立的 `front/` 和 `chatbot/` 演示应用，但它们不属于后端业务核心，不得挂载到 `backend/src/main.py`，也不能绕过后端 API 直接访问数据库。

## 二、必须遵守的架构不变量

### 1. TenantContext 不变量

`tenant_id` 必须来自服务端认证中间件构造的只读 `TenantContext`。

禁止：

- 从请求正文信任 `tenant_id`
- 允许 Agent 或 LLM 修改 `tenant_id`
- 使用不带 `tenant_id` 的数据库查询
- 只使用 `user_id`、`task_id`、`memory_id` 或 `workspace_id` 查询数据
- 后台任务在缺少 `tenant_id` 时继续执行

每一个数据库主键、唯一键、缓存键、向量元数据、图谱节点、图谱边、后台任务和审计记录都必须包含或绑定 `tenant_id`。

任何租户信息缺失或不一致时必须 fail closed。

### 2. 三层记忆不变量

三层记忆分别是：

- Working Memory：当前请求和当前任务运行状态
- Short-Term Memory：当前任务的可恢复检查点
- Long-Term Memory：经过治理的跨任务稳定信息

短期记忆不能转换、二次摘要或压缩为长期记忆。

长期记忆候选必须直接来源于原始事件窗口及其证据。

### 3. Consolidate Once 不变量

`Consolidate Once` 只处理当前租户中，收束游标之后的新增事件。

一次处理必须并行产生三个兄弟结果：

```text
Evidence
TaskCheckpoint
LongTermCandidate[]
```

禁止实现为：

```text
工作记忆 → 短期摘要 → 长期摘要
```

只有三个结果全部成功保存后，才能推进收束游标。

执行失败时不得丢失事件，也不得推进游标。

### 4. MemoryService 接口不变量

上层业务只允许调用：

```python
MemoryService.write(ctx, request)
MemoryService.read(ctx, request)
MemoryService.gc(ctx, request)
```

内部动作映射为：

```text
write → 01 原始写入、02 暂存、05 沉淀
read  → 03 唤回、04 调用
gc    → 06 释放
```

内部动作不能被设计成第四层记忆。

### 5. LLM 权限不变量

LLM 只能返回结构化候选或建议。

LLM 可以参与：

- 任务检查点摘要
- 对话切块
- 长期候选抽取
- 检索计划生成
- 重复、冲突或低价值建议

LLM 不得：

- 直接执行 SQL
- 直接修改记忆状态
- 直接删除记忆
- 直接决定租户权限
- 直接选择最终返回的数据库记录
- 直接修改版本关系
- 绕过 schema 和证据校验

最终写入、合并、替代、归档和删除必须由确定性代码执行。

### 6. 主记录与索引不变量

PostgreSQL 中的长期主记录是唯一事实来源。

以下内容都是派生访问路径：

- exact key
- vector index
- graph projection
- cache

派生索引只保存或返回 `memory_id`。

最终结果必须使用：

```text
tenant_id + memory_id
```

重新读取状态为 `active` 的长期主记录。

索引构建失败不能回滚已经成功保存的主记录。

### 7. 删除不变量

用户明确删除时，只能处理当前租户的数据。

需要处理：

- 长期主记录
- 版本内容
- 证据关联
- exact key
- vector index
- graph projection
- cache

删除后可以保留最小审计凭证，但审计中不能保留已删除正文，也不能泄露其他租户内容。

# 提示词 3：实现 MemoryService.write 和 Consolidate Once

本阶段实现完整写入链路。

## 一、统一写入入口

实现：

```python
MemoryService.write(
    ctx: TenantContext,
    request: WriteRequest,
) -> WriteResult
```

`WriteRequest` 使用可区分联合类型，至少支持：

```text
event
consolidate
promote_candidates
```

不要为三个动作建立三个对外 Service。

## 二、原始事件写入

`event` 模式需要：

- 生成或接收 event_id
- 按 tenant_id 幂等保存
- 原始正文不可修改
- 保存 session_id、task_id、role、content、event_type、source、created_at
- 保存文件、工具或产物引用
- 更新当前 Working Memory
- 计算是否达到窗口收束条件

建议支持以下收束原因：

```text
message_count
token_ratio
idle_timeout
step_completed
task_switched
session_ended
explicit_remember
manual
```

阈值必须来自配置，不要硬编码在 Service 中。

## 三、Working Memory

Redis 中保存当前运行对象，至少包括：

```text
identity
current_task_state
conversation_window
tool_and_file_results
immediate_instructions
excluded_paths
```

任何 Working Memory 访问都必须使用：

```text
tenant_id + workspace_id
```

## 四、Consolidate Once

实现：

```python
ConsolidateOnce.execute(
    ctx: TenantContext,
    workspace_id: str,
    trigger: ConsolidationTrigger,
) -> ConsolidateOnceOutput
```

执行步骤：

1. 按 `tenant_id + workspace_id` 获取锁
2. 读取 consolidation cursor
3. 查询游标之后的新事件
4. 如果无新增事件，返回幂等结果
5. 保护用户明确事实、决策、约束和来源
6. 调用 `Consolidator` 端口
7. 校验结构化输出
8. 同一事务写入 Evidence
9. 写入 TaskCheckpoint
10. 写入 LongTermCandidate
11. 三类结果成功后推进 cursor
12. 提交事务
13. 发布候选治理 Outbox 任务

输出必须是：

```python
class ConsolidateOnceOutput:
    evidence: list[Evidence]
    task_checkpoint: TaskCheckpoint | None
    long_term_candidates: list[LongTermCandidate]
    cursor_before: str | None
    cursor_after: str | None
```

## 二、支持的治理动作


含义：

```text

reason
confidence
uncertainties
```

- normalized_key 是否冲突
- 目标主记录是否属于当前 tenant_id
- 当前版本是否仍为 active
- 状态转换是否合法

## 四、版本策略

所有修改必须：

1. 保存旧版本快照
2. 增加版本号
3. 更新 supersedes/superseded_by
4. 写入审计
5. 产生索引更新 Outbox 任务

索引任务至少包括：

```text
exact
vector
graph
cache
```

索引失败时：

- 主记录仍然有效
- index projection 标记为 failed 或 stale
- 可以按 tenant_id + memory_id + version 重试
- 不允许扫描其他租户

## 五、图谱投影规则

实现基础规则：

- 偏好类内容通常生成向量
- 稳定实体关系生成 graph edge
- 同时具有语义和关系价值时，两类索引都生成
- 临时状态、低置信度推断和原始事件不生成正式索引

图谱第一版使用 PostgreSQL：

```text

```

通过 `GraphStore` 接口隔离具体实现。


`mode`：

```text
AUTO
META
RESUME
EXPRESS

```

## 二、各模式职责

### META

只返回控制信息：

```text
tenant 内用户信息
Agent 权限
允许的 scope
可用记忆类型
检索预算
系统限制
```

META 不返回其他租户内容。

### RESUME

按：

```text
tenant_id + task_id
```

获取同一任务的最新有效 TaskCheckpoint。

禁止只按 task_id 查询。

### EXPRESS

用于已知：

```text
memory_id
memory_key
type + normalized_key
```

不调用 LLM，不进入向量和图谱。

### QUICK

以向量召回为主：

```text
query embedding
→ pgvector
→ memory_id
→ tenant-scoped canonical reread
```

### NORMAL

支持：

- 查询改写
- 多子查询
- 向量召回
- 精确条件过滤
- 一跳关系补充
- 必要时证据回查

### DEEP

在 NORMAL 基础上支持：

- 多跳关系查询
- 原因和影响关系
- 多种记忆类型组合
- 更完整的证据回查

## 三、AUTO 路由

使用确定性规则优先判断：

- 已知 memory_id 或 key：EXPRESS
- 同一 task_id 恢复：RESUME
- 普通语义问题：QUICK
- 多条件问题：NORMAL
- 原因、影响、多跳关系：DEEP

只有复杂问题才调用 LLM 生成 `RetrievalPlan`。

## 四、RetrievalPlan

定义严格 schema：

```python
class RetrievalPlan:
    sub_queries: list[str]
    memory_types: list[MemoryType]
    scopes: list[ScopeFilter]
    entities: list[str]
    relations: list[str]
    time_range: TimeRange | None
    need_evidence: bool
    recommended_mode: RetrievalMode
```

LLM 只决定查什么，不决定最终返回哪条数据库记录。

## 五、公共检索处理链

所有模式必须经过：

```text
TenantContext
→ META 作用域约束
→ 索引召回 memory_id
→ tenant_id + memory_id 回读主记录
→ active/valid 状态过滤
→ 去重
→ 排序
→ 预算控制
→ Context Package
```

排序第一版使用可配置确定性公式，综合：

```text
semantic relevance
confidence
importance
explicitness
freshness
retrieval_weight
scope match
```

不要把权重写死在代码分支中。

## 六、Context Package

定义：

```python
class ContextPackage:
    meta: ContextMeta
    task_checkpoint: TaskCheckpointView | None
    facts: list[MemoryContextItem]
    preferences: list[MemoryContextItem]

    progress: list[MemoryContextItem]
    evidence: list[EvidenceExcerpt]
    excluded_memory_ids: list[str]

```

每个 `MemoryContextItem` 至少包含：

```text
memory_id
memory_type
content
confidence
scope
version
matched_reason

```

不能把数据库全部字段原样注入 Agent。

## 七、使用统计

区分：

```text

```

只有实际进入 Context Package 的记录才增加 `use_count`。

仅被索引召回但最终过滤掉的记录不能增加 `use_count`。

- A、B 租户使用相同 memory_id 时互不影响
